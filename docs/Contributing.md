# 🌿 Contributing to Kallora

Thanks for stopping by.  
Kallora is a project I’m building to **learn, grow my skills, and explore an idea I care about**. It’s open source so people can see the work and, if they want, contribute thoughts or small improvements.  

This isn’t a “community-driven” project (at least not right now), so think of contributions as *advisory* rather than *hands-on building*.  

---

## 🎯 What this project is (and isn’t)

- **Is**: a portfolio + sandbox where I’m testing design, code, and product ideas.  
- **Isn’t**: an open “anyone pick up tasks” type of project. My Notion board is for my own roadmap.  

---

## ✅ Cool things to contribute

- **Ideas**: If you see a better way to architect something, suggest it. Just explain *why*.  
- **Design feedback**: Layout, UX, or code style notes are welcome.  
- **Bug reports**: If you try the repo and hit errors, open an Issue.  
- **Small fixes**: Docs, typos, small refactors.  

---

## 🚫 Not really open right now

- Taking tasks directly from my Notion board.  
- Dropping huge feature PRs without prior discussion.  
- Forking and trying to present it as “the Kallora project” (forks for learning = fine).  

---

## 🔄 How to contribute

1. **Open an Issue first**  
   - Bug? → Use the bug template.  
   - Proposal? → Use the suggestion template.  
   - Don’t just drop code — context matters.  

2. **Discuss**  
   - I’ll respond. If it fits, cool. If not, also cool.  

3. **Pull Request (if agreed)**  
   - Keep it scoped.  
   - Reference the Issue it fixes.  
   - Explain what you did and why.  

---

## ⚖️ Forking

- Standard GitHub rules apply — you can fork, remix, play with the code.  
- If you publish something based on it, credit the repo.  
- The brand *Kallora* and the project’s direction stay personal.  

---

## 📜 Ground rules

- Be clear and constructive.  
- Respect boundaries (this is my learning ground).  
- Keep it professional. I'm pretty chill but don't spam me 

---

That’s it — thanks for understanding.
